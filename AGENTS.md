## Project conventions

The app is cut back to its foundation (auth, users/roles, change logs). The removed business features
(warehouse, loom, purchasing, sales, tax, accounting, bank book…) are documented in `docs/FEATURES.md`;
their code is in git commit `adfcd6e`.

- **Client-only Firebase, no backend.** `lib/firebase.ts` exports `auth` and `db`. There is no server code, firebase-admin or API route. The only server-side piece is `proxy.ts`: it redirects to /login when the "signed in" cookie (`lib/auth-cookie.ts`, set by `AuthProvider`) is missing; it is a hint, not security.
- **Auth:** `useAuth()` from `components/auth-provider.tsx`. Pages under `app/(app)/` are protected by `app/(app)/layout.tsx`. Each login user has a `users/{uid}` profile, created on first login.
- **Roles:** `users/{uid}.role` = `developer` > `master` > `admin` > Staff (empty). **Master and Developer are allowed in every feature.** Roles are changed on the Pengguna page by Master/Developer only, for users ranked below them and only to a role below theirs (so a Developer can never be changed, a Master only by a Developer); `roleRank()` in `components/auth-provider.tsx` and `rank()` in `firestore.rules` must match. The first Developer is set in the Firebase console. Use `useIsAdmin()` / `useCanManageRoles()` (they already include Master/Developer) and the matching `isAdmin()` / `isSuper()` in `firestore.rules`. Any new role-gated feature must allow Master and Developer too.
- **Every write goes through `lib/db.ts`** (`addRecord` / `updateRecord` / `deleteRecord`), never Firestore's `setDoc`/`updateDoc`/`deleteDoc` directly. They write the change and its `logs` entry in one transaction, which is what the Riwayat perubahan page shows. Documents that change together: `transaction(async (w) => …)`; all-or-nothing and still logged.
- **Reading data:** `useCollection(path, { orderBy, desc, limit })` from `hooks/use-collection.ts` (realtime). Show lists with `components/data-table.tsx` by spreading the hook result: `<DataTable columns={...} {...result} />`.
- **Daftar akun** (`lib/accounts.ts`, `/accounts`): `accounts/{6-digit number}` (number = id, never changes; deactivated, never deleted), names id/en/zh, group, Excel group, `type` (`ACCOUNT_TYPES`: label, normal balance, first digit), normal balance, report line (optional, picked from **Baris laporan** `reportLines/{NR..|LR..}`, `lib/report-lines.ts`, `/report-lines`; standard NERACA/LABARUGI lines via `addStandardReportLines`). Save with `saveAccount`. Import from the client's COA workbook (`lib/account-import.ts`: no header, A number, B English, C Indonesian, rows without a number = group heading; existing accounts only get names/group).
- **Buku bank** (`lib/bank-book.ts`, `/bank`): own banks in `banks/{auto id}` (name + account no., managed in the page's "Rekening bank" dialog), rows in `bankTransactions` (amount + in / − out, voucher number BBM/BBK.YY.MM.NNNN from `counters/{BBM|BBK}-{bank}-YYYY-MM`, rows sharing a number = one voucher). Write with `saveBankRow` / `saveBankRows` / `updateBankRow` / `deleteBankRow`. Import from the client's BANK BOOK workbook (`lib/bank-import.ts`, one sheet at a time, sheet numbers kept). A journaled row (`journal` set) is locked (code and rules) until its journal is cancelled.
- **Jurnal buku bank** (`lib/journal.ts`, `/bank-journal`): each bank links to its account (`banks.accountCode`); each row gets a contra account (`contra`, `setContra`, kept after a cancel); `journalVouchers` writes one balanced `journals` doc per voucher number (bank net line + one contra line per row, `accounts` array, `source: {kind: "bank", bank, rows}`) and sets the rows' `journal`; `cancelJournal` deletes it and unlocks the rows. Opening-balance rows are not journaled. The contra can't be the bank's own account. Old-format docs from the removed version may still sit in `journals`; new ones are those with `source.kind == "bank"`.
- **Account links (the big rule)** (`lib/account-links.ts`): an account may be connected to other data via `accounts.link` (`AccountLink`, now only `"inventory"`). `LINKS[link]` is the single source of what that means: allowed account `types` (inventory: asset), user-facing `rules` (shown in Daftar akun), `problem(row)` (what a bank row must carry before journaling, e.g. `stock` item lines), `apply` / `undo` (effect on the linked data, run inside the journal's transaction; inventory: debit = stock in, credit = stock out, movements carry `source: {kind: "journal"}`). `journalVouchers` records applied rows in `journals.links` and `cancelJournal` undoes exactly those (refused if stock can't go back). A new link = new `AccountLink` value + `LINKS` entry + its row data on `BankTransaction` + its input in Jurnal buku bank; never put link logic elsewhere.
- **Ledger** (`lib/journal.ts`, `lib/ledger.ts`, `hooks/use-ledger.ts`): one `journals` collection, four sources (`source.kind`): `bank` (Jurnal buku bank), `manual` (Jurnal umum `/journals`, `saveManualJournal`, JV.YY.MM.NNNN), `opening` (Saldo awal `/opening-balances`, `saveOpening`, fixed id `SALDO-AWAL`, the only journal rules let be overwritten), `cogs` (HPP bulanan, id `HPP-YYYY-MM`). Journals are never edited; `cancelJournal` deletes (bank: unlocks rows + undoes links; HPP: only the latest month). Manual journals can't touch inventory-linked accounts. Read the ledger only through `useLedger()` (filters out the removed version's docs, which lack `total`) and sum with `netByAccount`. Reports: Buku besar `/ledger?account=`, Neraca saldo `/trial-balance`, Neraca `/balance-sheet` and Laba rugi `/profit-loss` (`lib/statements.ts`: rows by report line, accounts without one shown and flagged; Neraca sections by NR number, current-year earnings computed).
- **Inventory value & HPP** (`lib/costing.ts`): moving weighted average per item (`valueMovements`, `monthValues`); an in carries `value` (purchase line value from Jurnal buku bank, opening stock value), an out without `value` takes the average; usage = outs typed in Stok bahan baku (no `source`). Items keep their inventory account (`account`). Nilai persediaan `/inventory-value` compares stock value with the ledger per account. HPP bulanan `/cogs` (`computeCogs` / `postCogs`): usage → Dr 105201 / Cr item accounts; production costs (type production, not 51xxxx or xxx999) → Dr 105201 / Cr allocation account `xxx999` (or itself); WIP → 105301 → 510101 with typed WIP / FG month-end values (`COGS_ACCOUNTS`).
- **Inventory / Gudang** (`lib/inventory.ts`, `/inventory`, `/inventory-movements`): items in `inventoryItems/{auto id}` (unique `code` reserved in `inventoryCodes/{code}` via `claimCode`, name, unit, group, optional `department` code, live `stock`, active), every change in `inventoryMovements` (item, itemCode, itemName, unit, date, in, out, stockAfter, note, batch, by, savedAt). Stock changes only via `saveMovements` (many items at once, all or nothing, never below zero) or an item's opening stock in `addItem`; movements are never edited or deleted (fix with an opposite movement). Excel import `lib/inventory-import.ts` (A code, B name, C unit, D group, E opening stock, F department code or name; matched by code, else by name for items without a code; existing items only get code/name/unit/group). New collection names on purpose: the removed version's `materials` / `stockMovements` data may still be in Firestore.
- **Departemen** (`lib/departments.ts`, `/departments`): `departments/{code}` = { code, name, active } (the removed version's shape, its data reads again); code never changes, deactivated not deleted. Items link to one optionally; Stok bahan baku filters by it (`?department=`, `-` = none).
- **Data uji** (`lib/test-data.ts`, `/test-data`, Developer only): test data is marked UJI (bank account no. `UJI-…`, item code `UJI-…`, department code `UJI…`); `findTestData` / `clearTestData` delete it and everything hanging off it (rows, journals, counters, movements, codes, the HPP journals of its months, and the Saldo awal journal only when ticked), moving back real stock a test journal changed. The test scenario is November 2025 (`docs/data-uji/`), away from current months. There is no home page: `/` redirects to `/accounts`. Rules allow these deletes only for a Developer and only on UJI-marked docs. Accounts, report lines and logs are never deleted.
- **New page:** add `app/(app)/<name>/page.tsx` and one `{ title, url, icon }` under a section in `nav` in `components/app-sidebar.tsx` (also sets the header title). A new collection needs its own rule in `firestore.rules` (everything else is closed).
- **All UI text is Indonesian** (labels, buttons, messages). Dates use `id-ID` via `lib/utils.ts`. Code, comments and Firestore field names stay English.
- **Mandatory fields show `*`:** put `required` on the input inside `<Field>`; `FieldLabel` adds the red `*` automatically (CSS in `components/ui/field.tsx`). Don't type `*` by hand, and keep this class if `field` is ever re-added with `shadcn add --overwrite`. Optional fields have no `required`.
- **UI:** shadcn/ui (base-ui flavour: `render` prop instead of `asChild`). Add components with `npx shadcn@latest add <name>` only when needed. Dropdowns use `components/simple-select.tsx`.
- **Colours:** black & white is the main palette (primary buttons, text, the active menu item). Colour is support only, via theme tokens in `app/globals.css`: brand blue `#2C3480` (`--brand`, `bg-brand-soft`, `--secondary`, `--ring`; sidebar section labels, info badges, total rows), a faint brand tint on greys and borders (the sidebar background stays white), `--success` (green: success, money in) and `--warning` (amber: needs a look), each with a `-soft` background. Badges: `variant="success" | "warning" | "brand" | "destructive"`. Red (`--destructive`) is only for errors and deletions.
- **Feedback:** every user action that writes shows a toast (`import { toast } from "sonner"`; `<Toaster />` is in `app/layout.tsx`): `toast.success(…)` naming what was saved, `toast.error(err.message)` on failure (never `alert`). Dialogs that already show an inline error keep it and only add the success toast.
